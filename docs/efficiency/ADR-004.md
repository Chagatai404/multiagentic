# ADR-004: E4 opt-in repair economies

Status: accepted implementation scope, 2026-10-26. Base: E3 commit `c5cf222`.

The repair loop already stops on identical failure signatures, unavailable checks and
the repair ceiling. E4 removes two remaining kinds of spending that cannot change the
outcome, without dropping any required role, check or inspection step.

## Decision

Two `workflow` settings, both **off by default** (project/user YAML; plan nodes inherit
the project workflow):

- `repair_headroom: true` admits a repair only when the task's remaining model calls
  cover the debugger and, when review is required, the fresh review of the repaired
  tree, and when debugger/reviewer role call allocations are not exhausted. A
  check-failure repair that cannot finish blocks before the debugger (resume re-runs
  checks after an explicit extension). A review repair is still recorded before the
  pause, so an extension runs the debugger rather than a new review. Without it,
  the debugger may spend the last call and the task then pauses before review.
- `stop_unchanged_repairs: true` pauses when a debugger call leaves the workspace
  byte-identical to the digest recorded when the repair was scheduled (event
  `repair_unchanged`). It skips re-running checks on an unchanged tree and, after
  review findings, an extra reviewer call on the same content. The task stays at
  `implemented`: inspect or edit the worktree, then `eng resume` re-runs checks.

Repair attempts record `base_digest`; legacy attempts without it are unaffected.

## Why opt-in

With both settings on, ten existing fixture flows end earlier: their scripted
debugger reapplies identical edits, and a nondeterministic real reviewer might accept
an argued no-change repair. Neither effect is measured on live models, so the
previous behaviour stays the default. E5 presets enable the settings explicitly.

## Unchanged

Completion still requires required checks to pass, required planning and review, and
human approval for high risk. Unknown provider outcomes still require inspection and
`--verify-only`. Nothing here retries automatically or replays an uncertain call.
