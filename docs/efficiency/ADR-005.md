# ADR-005: E5 operating presets

Status: accepted implementation scope, 2026-10-26. Base: E4 commit `bcba72a`.

Until E5, economy/balanced/rigorous were prose examples. E5 implements them as named,
explicit bundles of existing settings. They are operator shorthand, not measured
optima: no live calibration backs any value.

## Decision

`eng run --preset NAME` and plan `preset: NAME` apply one profile:

| Preset | Repairs | `repair_headroom` | `stop_unchanged_repairs` | Packet chars |
|---|---:|---|---|---:|
| economy | 0 | on | on | 12,000 |
| balanced | 1 | on | on | 16,000 |
| rigorous | 2 | off | off | 24,000 |

The model-call allowance is **derived, not fixed**: the initial required roles from
the existing classification (planner if complex, engineer, reviewer if required) plus
`repairs × (1 + reviewer)`. A preset therefore cannot under-budget required planning
or review. A small low-risk task in economy gets one call; a complex task in balanced
gets five. Changed-path escalation can still require an explicit extension.

Precedence: project/user config → preset → explicit options. For `eng run`, explicit
`--model-calls` / `--max-repairs` and other budget options win. For plans, a preset
sits beneath `node_budgets` / `node_max_repairs` and node `budgets` / `max_repairs`.
Plans freeze each node's resolved budgets, repair ceiling and workflow
(`effective_workflow`) at creation; `eng plan preview` shows them. Tasks record
`spec.preset` for audit.

## Unchanged

Presets never change classification, risk, required roles, approval, checks,
ownership, protected paths, reported-usage thresholds, role sublimits, provider/model
routing or concurrency. Concurrency stays an explicit plan field (default 1).

## Not implemented

Expanded dashboards were not added; existing `eng usage` / `eng plan usage` reports
group by selected provider/model and include outcome counts. Choosing a preset by
evidence needs the owner-authorized live protocol in [BENCHMARKS.md](BENCHMARKS.md).
